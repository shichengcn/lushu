## 二、怎么导入大模型

### 方式 A（推荐 · 最省事）：上传合并 MD

1. 打开支持长文档的模型（ChatGPT / Claude / 豆包 / Kimi / 通义等），新建对话；
2. 上传 `青甘大环线知识库_全文合并.md`（约 70 万字符，若模型上下文不足，改用方式 B 或只上传相关分册区间）；
3. 先发下面的"系统设定"，再发具体问题。

**系统设定（每次对话开头先贴这段）：**

```
你是我的青甘大环线自驾行程规划助手。我已上传《青甘大环线知识库_全文合并.md》。
硬约束：2026-09-25 至 10-06 共 12 天；4 名成人 1 辆 SUV；逆时针方向；9-25 中午落地西宁机场取车、D10 晚西宁市区还车、D11 高铁去兰州、D12 兰州中川机场返程；每天 08:00 前发车、最晚 18:00 前到店。
回答规则：
1. 只用知识库中的数据，禁止补充知识库里没有的价格、里程、开放时间；缺失就明确说"知识库未覆盖"。
2. 知识库中标注"存在差异，出行前确认"的字段，必须同时给出各口径并提示二次确认。
3. 涉及高原健康、封路、加油、限速的结论，必须引用对应分册（如"分册05 §5.2 当金山"）。
4. 输出用中文，能做成表格就做成表格。
```

### 方式 B（省 token）：上传 JSON + CSV

- 结构化问答（预算、门票、酒店、逐日里程）→ 只上传 `knowledge_base.json`；
- 只做景点取舍 → 只上传 `pois.csv`；
- 只做单日重排 → 只上传 `itinerary_days.csv`；
- 需要长文细节（一手评价、注意事项原文）时，再补上对应分册的 Markdown。

### 方式 C：接进自己的程序 / RAG

```python
import json, csv

kb = json.load(open("qinggan_kb/exports/knowledge_base.json", encoding="utf-8"))
day7 = next(d for d in kb["itinerary"] if d["day"] == 7)          # 国庆首日无人区
free_niche = [p for p in kb["pois"] if p["is_niche"] == 1 and p["ticket_cny"] == "0"]
fuel_top = [f for f in kb["driving"]["fuel_stops"] if f["level"] == "最高级"]

with open("qinggan_kb/exports/pois.csv", encoding="utf-8-sig") as f:
    pois = list(csv.DictReader(f))
```

> 切片建议：RAG 场景下按 `### ` 小节切分 03/04 两册（每个景点一篇，字段固定），其余分册按 `## ` 章节切分。

## 三、三个可直接复制的 Prompt 模板

### 模板① 按天规划（逐日细化 / 时间线重排）

```
请基于知识库，把 D6（2026-09-30 敦煌→苏干湖→阿克塞石油小镇→黑独山→大柴旦，约 500km）细化成一份可执行的当日计划，要求：
1. 用表格给出时间线：时刻 / 动作 / 路段（国道或高速编号）/ 区间里程 / 该点海拔 / 停留时长；
2. 明确加油节点与"必须加满"的位置，以及无补给区间的公里数；
3. 标注当天的信号盲区路段与应对措施；
4. 单列"高原健康动作"：出发前、垭口、抵达大柴旦后分别要做什么，写出血氧阈值；
5. 单列"B 方案"：如果当金山 G215 仍在限时限向的应急通行状态，路线怎么改、哪个景点挪到哪天；
6. 最后给出 3 条当天最容易出事的风险点，并注明来自哪一分册。
把我未提供的信息标为"知识库未覆盖"，不要自行补充。
```

> 换天使用：把 D6 改成 D2—D12 中任意一天即可；想要全程版本就写"请对 D1—D12 逐天输出，并在最后汇总总里程、总门票、总住宿"。

### 模板② 按兴趣选景点（取舍 / 加点 / 减点）

```
我们 4 人的偏好是：①湖泊与盐湖类风光优先 ②愿意为"人少且免费"的点绕路 30 分钟以内 ③不接受非铺装碎石路（家用两驱 SUV）④每天车程不超过 500km。
请基于 pois.csv / knowledge_base.json 的 pois 字段：
1. 从 78 个景点中筛出符合上述条件的"必去"清单，输出表格：景点 / 片区 / 门票+观光车 / 建议时长 / 海拔 / 推荐结论 / 建议插入天数 / 绕路成本；
2. 再给一份"明确放弃"清单，逐条写放弃理由（道路封闭、季节不对、绕路超过半天、车型不匹配等）；
3. 给出把筛出的加点插进 12 天主方案后的调整方案：哪天加什么、要压缩或删掉什么，并给出调整后的当日里程与预计到店时间；
4. 凡是需要四驱、无信号、无救援的点位，单独标红提示，并说明触发放弃的条件。
只用知识库数据，门票有多个口径时全部列出并提示"出行前确认"。
```

### 模板③ 风险排查（行前体检 / 出发前 72 小时）

```
请做一次出发前风险排查，输出 5 张表：
```

## 五、数据来源

导出层不新增任何事实，全部来自 `qinggan_kb/` 下 9 册（合计 6,229 行），而 9 册的原始来源为：

| 代号 | 来源 | 性质 |
|---|---|---|
| `doc2` | 用户本次 12 天逆时针行程主文档 | 行程骨架、门票、海拔、逐日注意事项、《国庆自驾避雷总清单》9 条 |
| `sheet` | 用户飞书行程表 D0—D12 | 真实酒店名与价格、逐点海拔、加油与路况备注（**日序为顺时针，本知识库只复用方向无关数据**） |
| `doc3` | 一手实走游记（国庆逆向 8 天，双人星级评分与真实支付价） | 唯一的一手体验与实付价来源 |
| `doc1` | 《2026青甘大环线11天自驾终极攻略》 | 四维方向评分、三档预算、拍照机位、穿搭、应急预案（**原文为五一版本，季节性数据不可直接套用**） |
| `research/A`、`research/B` | 2026-08 网络调研（柴达木小众点、甘肃祁连青海湖景点） | 小众点位、路况通告、封路与票价补充，原文保留 markdown 链接 |

**关键口径与冲突处理原则**（导出层同样遵守）：

1. **多来源票价/海拔/里程不一致时全部并列**，标注"存在差异，出行前确认"，预算取区间上限；
2. **不合并、不平均**冲突数据，也不臆造缺失值——缺失一律留空字符串或 `null`；
3. 星级两套口径（`🌟` doc3 实走 / `★` doc1 综合）**不可混用**；
4. 里程采用 doc2 逐日相加口径 ≈ 3,550—3,600 km，实际导航会更高，预留 +10% 约 3,900 km。
